Как считаю. «Прибыль видимая» = продажи − комиссия Ozon − закупка (закуп+Ермек+упаковка, без колонки L «Себестоимость») − вся реклама (клик + «оплата за заказ»). Это то, что можно проверить напрямую по API, SKU в SKU. Данные окна 26.07–25.08.2026 (31 день) — упирается в жёсткий лимit Ozon 32 дня для метода реализации; 25.07 не отдался (0 строк), поэтому фактическое окно — 31 день, не 32.

Оценка* без кредита — видимая прибыль минус пропорциональная (по доле продаж SKU) часть расходов, которые Ozon НЕ отдаёт по SKU через API: логистика, хранение, эквайринг/гибкий график, штрафы, возвраты (18,32% продаж — посчитано напрямую из реальных недельных кассовых данных партнёрской страницы за окно 24.07–23.08, по неделям колеблется 15,6–19,7%; более ранняя оценка 16% была занижена — уточнил 27–28.08) и НДС 22% от операционной прибыли (186 894 ₽ за окно). Это операционная нагрузка магазина, без учёта кредитов.
Оценка* с кредитом — то же самое, плюс доля кредитной нагрузки (152 336,33 ₽/нед, на 31 день — 674 632 ₽), распределённая пропорционально продажам SKU. Кредит — это финансовое обязательство, а не операционный расход конкретного товара, поэтому показываю отдельно: без кредита — сколько зарабатывает сам товар после реальных издержек Ozon; с кредитом — сколько остаётся после того, как товар «отработал» и свою долю текущих кредитных платежей. Обе колонки — ОЦЕНКА, не факт API: реальные логистика и хранение зависят от веса/габаритов и срока лежания товара на складе, а не только от суммы продаж — у крупногабаритных/медленных позиций реальная нагрузка может быть выше показанной здесь доли, у мелких/быстрых — ниже. Уверенность в этих колонках ниже, чем в «видимой прибыли»: ~70%.

Источники. Продажи/комиссия/закупка — POST /v1/finance/realization/by-day, по каждому дню окна 26.07–25.08.2026 (31 день) (Seller API), закупка — sku_cost_zakup.json. Реклама «заказ» (ALL_SKU_PROMO) — GET /api/client/statistics/all_sku_promo/orders/generate с timeBounds.from/to (Performance API); сверено против отчёта «по дням» того же метода — расхождение 0 ₽ за окно 26.07–25.08. Логистика/склад/кредиты/НДС для оценочной колонки — POST /v1/finance/cash-flow-statement/list (with_details) за недели, пересекающие окно, пропорционально дням пересечения.
Ограничения. (1) Логистика и хранение недоступны по SKU через API Ozon — только по счёту в целом, отсюда оценочная колонка. (2) Окно 31 день — короткое; часть SKU в нём имеют 1–3 дня с продажами (это отмечено ⚠ в комментарии) — для них вывод предварительный, не делайте необратимых решений по одной этой странице. (3) Атрибуция рекламы «заказ» — по колонке SKU (фактически проданный товар), не «SKU продвигаемого товара» — в 398 из 1632 строк отчёта они отличаются (кросс-продвижение); расход отнесён на факт продажи. (4) НДС и распределение общих расходов — линейная оценка пропорционально продажам, не бухгалтерский расчёт.
