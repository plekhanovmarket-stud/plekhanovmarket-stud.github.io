Ozon — Реклама: клики за 60 дней + статус «Оплаты за заказ»

Данные на 31 августа 2026 · период 02.07–30.08.2026 (60 дней), клики — сравнение первой полной недели окна (06–12.07) и последней полной недели (24–30.08)

Главное для решения. Кампания «Оплата за заказ — все товары» (ALL_SKU_PROMO, запущена 15.08) продолжает работать: по 7 отдельным дням, за которые в этой выгрузке сохранился файл кампаний (20, 24–27, 29–30 августа), на неё ушло суммарно 124 661 ₽ — и, как и раньше, Ozon не отдаёт по API ни одного заказа по ней (0 заказов, 0 ₽ выручки во всех 7 днях, при 8 670 кликах и 250 928 показах суммарно) — тот же подтверждённый тупик API, что и в прошлый раз (см. «Ограничения» ниже). Дневной расход на неё растёт: 13 326 ₽ (20.08) → 23 151 ₽ (30.08). Кликовая реклама тем временем продолжает сжиматься: расход на клики упал с 358 557 ₽ (неделя 06–12.07, начало окна) до 158 976 ₽ (неделя 24–30.08, конец окна) — в 2,3 раза, а ДРР по кликам за то же время улучшился с 13,58% до 11,33%. Полный дневной ряд кампаний за все 60 дней в этой выгрузке не сохранён — доступны только 7 выборочных дней, поэтому общий расход на «Оплату за заказ» за всё окно (60 дней) посчитать нельзя.

Как считаю. «Заказы» и «ДРР» посчитаны только по кликовой части — это единственное, что Ozon показывает по товарам. «ДРР» = расход / «Заказано на сумму» (это официальная метрика Ozon «ДРР (общий)», не узкая «ДРР в продвижении»). «Оплата за заказ» дана отдельной колонкой и не входит в расчёт заказов и ДРР — по ней заказов через API нет. В этом прогоне «оплата за заказ» для строк «Начало окна»/«Конец окна» показана как «—»: для 06–12.07 кампании ещё не было (запущена 15.08, ноль — реальный факт), а для 24–30.08 в выгрузке нет файла кампаний на все 7 дней недели (есть только 6 из 7) — сравнимую недельную сумму посчитать нельзя, точечные дни см. ниже.

Выводы и рекомендации

Сильные стороны.
1. Расход на клики со «Начала окна» (06–12.07) к «Концу окна» (24–30.08) снизился на 199 582 ₽ (358 557 → 158 976 ₽, −55,7%). ДРР по кликам при этом улучшился — с 13,58% до 11,33% — расход падал быстрее, чем «заказано на сумму» (−46,8%, до 1 403 458 ₽).
2. Товаров с расходом и нулевыми заказами (по кликам) стало меньше: 300 → 167 за неделю, бюджет на них упал с 38 375 ₽ до 20 596 ₽.
Слабые стороны.
1. По 7 отдельным дням с сохранённым файлом кампаний «Оплата за заказ» продолжает тратить бюджет (124 661 ₽ за эти 7 дней) без единого заказа через API — то же самое, что и раньше, просто дороже: за 60 дней полную сумму по ней посчитать нельзя (нет непрерывного файла).
2. За 60 дней 224 товара с расходом на клики так и не дали ни одного заказа — суммарно 42 346 ₽ (1,87% всего кликового рекламного бюджета периода) потрачены без отдачи.
3. Новая аномалия — SKU 4008388679, ДРР 201,6% на 5 980 ₽ расхода, см. выше.
4. Заказы (шт) по кликовой части упали ещё сильнее расхода в процентном выражении не везде — общее падение оборота компании за этот период (см. страницу 2) означает, что часть снижения «заказано на сумму» — это спад продаж вообще, а не только сокращение рекламы; отделить одно от другого по этим данным нельзя.
Рекомендации.
Мои рычаги: снять с продвижения или резко снизить ставку по SKU 4008388679 — освобождает часть от 5 980 ₽/60 дней. Пересмотреть 35 товаров из списка «Топ по ДРР» (порог включения — расход от 1 000 ₽ за 60 дней) с ДРР выше 40% (это в основном товары с мелким чеком, где реклама объективно невыгодна) — под пересмотром расход 210 563 ₽ за 60 дней, из них крупнейший — SKU 4008018838 («Розетка двойная внутренняя...», ДРР 41,3%, 21 912 ₽). По 224 товарам с нулевыми заказами — не снимать разом (42 346 ₽ за 60 дней это всего 1,87% бюджета, среди них могут быть новинки), а выгрузить список и сверить с датой старта продаж по каждому SKU.
Механики Ozon: восстановить непрерывный сбор файла кампаний (_daily/camp_*.json) на все 60 дней — без него нельзя ни оценить полный расход «Оплаты за заказ», ни надёжно сравнивать окна между собой. Продолжать сверять общую выручку магазина (не только рекламную) за сопоставимые периоды — единственный способ оценить реальный эффект кампании, раз Ozon не отдаёт атрибуцию по API. Если доля бюджета на неё продолжит расти без видимого роста общих продаж (страница 2) — сокращать её вручную.
Ограничения — прочитать перед тем, как принимать решения по этим цифрам.
1. Файл кампаний неполный. В этой выгрузке _daily/camp_*.json сохранён только за 7 из 60 дней окна (20, 24–27, 29–30 августа) — «Оплата за заказ» по остальным дням, включая «Начало окна» (06–12.07), посчитать нельзя. Сравнение «Начало окна»/«Конец окна» в этой странице — только по клику.
2. «Оплата за заказ» не разложена по товарам и не даёт заказов через API. Тот же тупик, что и в прошлых прогонах: GET .../statistics/all_sku_promo/{products,orders}/generate не отдаёт атрибуцию по SKU. Как обходной путь для страницы 2 используются начисления Seller API (MarketplaceServicePromotionWithCostPerOrder по отправлениям) — там есть привязка к SKU, но это уже другой источник, не рекламный API.
3. Реклама глубже 02.07.2026 по товарам недоступна в этой выгрузке — Ozon отдаёт историю асинхронного отчёта максимум на 60 дней назад. Раскладка за более ранние периоды возможна только пропорционально (оценка), это сделано на странице 2, не здесь.
