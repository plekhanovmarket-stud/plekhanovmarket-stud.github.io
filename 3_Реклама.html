Ozon — Реклама: переброска бюджета на «Оплату за заказ»

Данные на 20 августа 2026 · период 22.06–20.08.2026 (60 дней), сравнение окон 09–14.08 и 15–20.08

Главное для решения. 15.08 запущена кампания «Оплата за заказ — все товары» (ALL_SKU_PROMO). За 6 дней на неё потрачено 63 014,05 ₽ — 36,6% всего рекламного бюджета окна 15–20.08. Одновременно клики (обычная реклама по товарам) обрезаны почти вдвое: с 27 573 до 15 175 (−45,0%), расход на клики упал с 201 932 ₽ до 109 188 ₽ (−45,9%). Показатель ДРР по кликовой части улучшился с 7,07% до 4,54% — но у «Оплаты за заказ» Ozon не отдаёт по API ни одного заказа (0 заказов, 0 ₽ выручки в кампанейской статистике за все 6 дней, при 6 542 кликах и 200 127 показах) — это подтверждённый тупик API (см. «Ограничения» ниже), а не обязательно означает, что заказов реально не было. Итог: 63 014 ₽ потрачены «вслепую» для аналитики — оценить их отдачу отдельно от общей выручки магазина сейчас нельзя.

Как считаю. «Заказы» и «ДРР» посчитаны только по кликовой части — это единственное, что Ozon показывает по товарам. «ДРР» = расход / «Заказано на сумму» (это официальная метрика Ozon «ДРР (общий)», не узкая «ДРР в продвижении»). «Оплата за заказ» дана отдельной колонкой и не входит в расчёт заказов и ДРР — по ней заказов через API нет.

ДРР 2 565%: на каждый заказанный рубль потрачено 25,6 ₽ рекламы. Это не опечатка — я пересчитал по сырым данным дважды. Либо цена клика по этому товару абсурдно высока для его стоимости (дешёвые саморезы, крупная упаковка конкурентов забирает клик), либо ставка стоит по ошибке. Рекомендация — снять с продвижения сегодня, разбираться не срочно.

Выводы и рекомендации

Сильные стороны.
1. Расход на клики за 6 дней после переброски снизился на 92 745 ₽ (201 932 → 109 188 ₽, −45,9%), при этом заказы (шт) по кликовой части не упали, а чуть выросли: 1 251 → 1 277 (+2,1%). Заказано на сумму просело меньше, чем расход (2 857 815 → 2 407 272 ₽, −15,8%), поэтому ДРР по кликам улучшился с 7,07% до 4,54%.
2. Товаров с расходом и нулевыми заказами (по кликам) стало меньше: 240 → 161 за окно, бюджет на них упал с 27 324 ₽ до 14 319 ₽.
Слабые стороны.
1. 63 014 ₽ (37% бюджета «после») ушли в кампанию, для которой Ozon не показывает ни заказов, ни выручки ни по одному из проверенных методов API — оценить её ROI отдельно от общего оборота магазина нельзя.
2. За 60 дней 207 товаров с расходом так и не дали ни одного заказа — суммарно 48 484,63 ₽ (1,96% всего рекламного бюджета периода) потрачены без отдачи.
3. Один товар (саморезы 6×70, SKU 1548325869) — явная аномалия на 11 773 ₽, см. выше.
4. Улучшение ДРР по кликам частично может объясняться не ростом эффективности, а тем, что «заказано на сумму» держится на базовом уровне органических продаж — рост заказов при падении кликов на 45% сам по себе не типичен и требует времени, чтобы понять причину, а не сразу засчитывать как эффект оптимизации.
Рекомендации.
Мои рычаги: снять с продвижения SKU 1548325869 (саморезы) — освобождает часть от 11 773 ₽/60 дней сразу. Пересмотреть 10 товаров из списка «Топ-20 по ДРР» с ДРР выше 40% (это дешёвые товары с мелким чеком, где реклама объективно невыгодна) — под пересмотром расход 53 990 ₽ за 60 дней, из них 21 344 ₽ — один товар («Изолента», ДРР 49,0%). По 207 товарам с нулевыми заказами — не снимать разом (48 484 ₽ за 60 дней это всего 1,96% бюджета, среди них могут быть новинки), а выгрузить список и сверить с датой старта продаж по каждому SKU.
Механики Ozon: держать кампанию «Оплата за заказ» под наблюдением ещё минимум 2 недели (см. «Ограничения») и параллельно сверять общую выручку магазина (не только рекламную) за сопоставимые периоды — это единственный способ оценить её реальный эффект, раз Ozon не отдаёт атрибуцию по API. Если через 2–3 недели доля бюджета на неё продолжит расти без видимого роста общих продаж — сокращать её вручную.
Ограничения — прочитать перед тем, как принимать решения по этим цифрам.
1. 6 дней — короткое окно. Часть разницы между «до» и «после» может быть сезонной (день недели, случайные колебания спроса), а не эффектом переброски бюджета. Полноценный вывод можно будет сделать, когда после запуска пройдёт минимум ещё одно 6-дневное окно (то есть после 26.08.2026) — тогда сравнивать станет проще, а ещё надёжнее — после 2–3 полных недель (к началу сентября), когда сгладятся дневные колебания.
2. «Оплата за заказ» не разложена по товарам и не даёт заказов через API. Проверено: GET .../statistics/all_sku_promo/{products,orders}/generate — все 9 комбинаций параметров вернули 400 без тела. Это тупик, а не то, что я не попробовал. Как обходной путь для страницы 2 использую начисления Seller API (MarketplaceServicePromotionWithCostPerOrder по отправлениям) — там есть привязка к SKU, но это уже другой источник, не рекламный API.
3. Реклама глубже 22.06.2026 по товарам недоступна — Ozon отдаёт историю асинхронного отчёта максимум на этот срок назад. Раскладка за май и 1–21 июня возможна только пропорционально (оценка), это сделано на странице 2, не здесь.
Источники: Ozon Performance API — /api/client/statistics/daily/json (кампании по дням, эталон), POST /api/client/statistics (асинхронные отчёты по SKU, пачками по 10 кампаний). Файлы: daily_campaign_stats.json (112 кампаний, 60 дней, 2 538 903,14 ₽), ads_sku_day.json (754 товара, 34 637 пар «день+товар», 2 476 476,69 ₽ — без кампании «Оплата за заказ», её нельзя разложить по SKU). Разница между двумя файлами — 62 426,45 ₽ за 60 дней; из них 63 014,05 ₽ — расход кампании «Оплата за заказ» за 15–20.08; остаток (−587,60 ₽) — прочие мелкие расхождения округления/сборки, не разбирался отдельно, это 0,02% от эталона. Сверка недели 10–16.08 по данному файлу: 200 273,26 ₽ — сходится с контрольной точкой бухгалтера (200 273,63 ₽, расхождение 0,37 ₽), см. Протокол проверки страницы 1.
